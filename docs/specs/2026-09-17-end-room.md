# TDD Spec: End a shared game

_Status: Complete_

## Intent and scope

Give the host an explicit End game action, including mid-round, and give everyone
a clear route back to create a new room. Closing keeps completed round scores and
does not score an unfinished hand or declare an artificial winner.

## Expected outcomes and invariants

- A host can confirm End game from the room header; cancellation changes nothing.
- Closing is persisted as an authenticated, revision-checked, idempotent room event.
- Closed rooms reject joining, dealing and card commands. Existing private-card
  visibility and historical seat ownership remain intact.
- Every connected player sees Game ended and Leave room / Create new room controls.
- Leaving a closed room removes its recent-room shortcut; history remains stored.

## Red → green verification

- Unit tests first: host authorization, stale requests, duplicate end, persistence,
  unchanged scoring and rejected actions after closure.
- Browser test: two players, cancel then confirm, both receive closure, reload keeps
  closure, leave then create a different room.
- Run focused tests, `npm run check`, `npm run build`, and the Worker browser flow.

## Boundaries

No active-seat removal or rule changes. Completed-game rematches remain available
until the host explicitly closes the room. Existing rooms require no migration.
